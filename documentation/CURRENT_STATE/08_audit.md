## 4. Custom Edit Preservation (HookStore.load())

**Implementation**: `plan_data.dart:56`:

```
Load saved hooks from hooks.json → Map<String, HookIdea>
For each hook in kDefaultHooksWithRewrite:
  1. If saved version exists:
     a. If kRewrittenStories has a rewrite for this ID AND
        saved.storyDetail is non-empty AND
        saved.storyDetail differs from original built-in → use saved (user edit wins)
     b. Otherwise → use saved with rewrite applied (if rewrite exists)
  2. If no saved version → use kDefaultHooksWithRewrite value
Append custom hooks (h.custom == true) from saved store
```

**Risk**: If a user edits a hook whose storyDetail edit matches the **original built-in** (not the rewrite), the rewrite is silently applied instead of their edit (because the edit is detected by comparing to `defaults[d.id]!` not to `kRewrittenStories[d.id]`).

**Custom hooks** (marked `custom: true`) are preserved via `saved.values.where((h) => h.custom)`.

## 8. Content ID Linkage (stable IDs?)

### ID generation is timestamp-based (NOT content-derived)
| Entity | File:Line | ID Pattern |
|--------|-----------|------------|
| ContentPackage | `content_generator.dart:186` | `DateTime.now().millisecondsSinceEpoch.toString()` |
| ContentLibraryItem | `content_library.dart:201` | Same timestamp pattern |
| Project/Story | `main.dart:769` | Same timestamp pattern |
| Video file | `main.dart:4471` | `reel_${DateTime.now().millisecondsSinceEpoch}.mp4` |
| PostRecord | `posting_kit.dart:171` | `post${DateTime.now().millisecondsSinceEpoch}` |
| Custom HookIdea | `plan_screen.dart:126` | `c${DateTime.now().millisecondsSinceEpoch}` |
| QuickIdea (runtime-created) | `quick_content.dart:780` | Same timestamp pattern |
| IdeaInboxItem | `quick_content.dart:3081` | Same timestamp pattern |
| ContentLibraryItem (via saveIdea) | `content_service.dart:56` | Same timestamp pattern |

**Problem**: IDs are ephemeral timestamps, not content-derived hashes. Two rapid operations can collide. There's no guaranteed linkage between a ContentPackage and its video file or post record except through in-memory project objects.

### Content-derived IDs (partial exception)
Some downstream entities use content-derived IDs to link to a parent, but the base ContentPackage/Idea ID is still timestamp-based:

| Entity | File:Line | ID Pattern |
|--------|-----------|------------|
| PromptVault item | `prompt_vault.dart:220` | `${contentId}_${type.name}_v$nextVersion` |
| VideoAsset | `video_library_store.dart:82` | `${contentId}_v$nextVersion` |
| QualityReport | `quality_check_center.dart:294,308,327,340,351` | `${contentId}_script_*` |
| FLWP content ID (via title) | `content_studio_screens.dart:35,49` | `FLWP-${slug(title)}` |

The `contentId` passed to these is either a ContentPackage.id (timestamp) or a `FLWP-$slug` derived from the story title via `_contentIdFromTitle()`. ContentLibraryItem carries `sourceIdeaId` (`content_library.dart:29`, `content_library_service.dart:502`) to trace back to the originating idea.

### PostLogStore linkage
`PostLogStore` (plan_data.dart:275) stores `PostRecord` with fields: `id`, `title`, `projectId`, `hookId`, `bucket`, `postedAt`, `views`, `likes`, `comments`, `saves`, `shares` (plan_data.dart:207-260). **No `contentId`, `projectName`, or `format` fields exist** on PostRecord. The linkage to a project is via `projectId` at `posting_kit.dart:173`:
```dart
PostRecord(
  id: 'post${DateTime.now().millisecondsSinceEpoch}',
  title: _title,
  projectId: widget.projectId,
  postedAt: DateTime.now(),
)
```

## 10. Migration Plan (to consolidate to single source of truth)

### Phase 1: Data layer
1. **Remove safety hooks double-add** in `content_library_service.dart:406` — kDefaultHooksWithRewrite already includes them
2. **Fix `asset_completeness_service.dart:95`** — change from `kDefaultHooks` to `HookStore.load()` so user edits are checked
3. **Fix `plan_data.dart:66`** — change from `kDefaultHooks` to `kDefaultHooksWithRewrite` for the defaults map
4. **Replace timestamp-based IDs** with content-derived IDs (hash of content) for ContentPackage, Project, PostRecord

### Phase 2: Navigation
1. **Remove `onManageVideos` callback** from ContentStudioHome — it's always null
2. **Wire or remove QuickContentScreen cluster** (8 screens in quick_content.dart)
3. **Decide on StoryInputScreen vs StoryScreen** — both appear to be reel writers. StoryScreen (main.dart) is the live entry point
4. **Decide on ReviewIdeaScreen vs IdeaReviewScreen** — verify they are genuinely different screens

### Phase 3: Gemini
1. **Two parallel Gemini paths exist** (see 04_generation.md §5):
   - **Path A** (`gemini_call.dart`): raw HTTP, model `gemini-3.8-flash`, 4-model fallback chain — robust retry/fallback
   - **Path B** (`gemini_client.dart`): SDK-based, model `gemini-3.5-flash-lite`, **NO retry/fallback** — used by `AiContentServiceImpl`
2. **Verify Path B usage**: `AiContentServiceImpl` is created at main.dart:96 but check if any screen actually calls it. Path B's `gemini-3.5-flash-lite` with no fallback is the likely cause of "works 2/10 times"
3. **Path A 400 handling**: `content_studio_service.dart:96-98` says "400 = model rejected the request (e.g. thinkingConfig unsupported). Try the next model." Each model in the chain has its own 20/day quota — a 400 still consumes a quota unit even though the call fails
4. **Consolidate to one Gemini path**: Either add retry/fallback to `gemini_client.dart`, or route all calls through `geminiPost()`
5. **Consider caching Gemini responses** — avoid repeated calls for the same idea

### Phase 4: Tests
1. **Add widget tests for TimedScriptScreen** — the 4-step wizard is the core workflow but has no widget tests
2. **Add tests for StoryScreen** — the main Create flow
3. **Add tests for ContentLibraryService merge logic** — including the safety hooks double-add bug
